# 手语词语采集与分类方案（待确认词表）

本方案依据用户提供的 P1–P13 对话及 `E:\QQ_Download\data_raw.csv`。仅分析与设计，未修改示例文件、线上数据库或 CSV 导出逻辑。默认目标为先识别独立手语词，再重组成句子，实际手语词元应由示范者确认。

## 示例数据结构

示例按 GB18030 解码：77 列、122,066 行、7 位采集人、10 个词标签。按 worker/v/label/active_hand/sample_id 组合统计为 2,144 个样本。

| 字段 | 含义及使用建议 |
|---|---|
| worker | 采集人。推荐使用稳定的编号，如 P001；姓名单独维护映射 |
| v | 示例值 slow、medium、high；看起来为速度档，需用户确认 |
| label | 一个完整手语词元的标签，不直接使用中文逐字分词 |
| active_hand | 此动作主要使用 left/right/both；不是采集数据的手别，两手都应保留 |
| sample_id | 一次完整动作的编号。示例中的 gt_001 会在不同条件下重复，应用组合键或全局唯一 sample_id |
| timestamp/ms | 示例中各手时间戳存在很大偏移，不能按跨手时间戳直接拼接 |
| frame_id | 一次动作内部的帧序号，从 0 开始；同一帧左右手共用 |
| hand_type | 当前行属于 left 或 right |
| f_0_s1…f_4_s2 | 10 路指部 IMU，每路加速度三轴、角速度三轴，共 60 个数值 |
| dorsal_* | 第 11 路 IMU，六轴及磁力计三轴，共 9 个数值 |

示例词标签：我、你、好、早上、很、认识、谢谢、高兴、在、家。

按组合样本及 frame_id 检查，61,032 帧同时有左右手，另有 2 个只有一手的帧。已配对行的时间戳绝对差为 0–3,767,617 ms。这说明相同 frame_id 的原时间戳并非可靠的同步证据；未对原文件做修复或删除。

## 分类层次与采集操作

分类：采集人 → 手语词元 → 速度 → 重复样本 → 帧 → 左右手。每次 GPIO4 开始至再次 GPIO4 结束，先按“一次动作、一个词标签”管理。

网页建议增加“采集标注”页，录制前填写：采集人、词元、速度、动作手、备注。显示当前样本编号、两手在线状态、有效通道以及录制状态。结束后显示时长、帧数、完整双手帧数，允许标为有效、待检查或重录。重录生成新编号，旧样本保留并标为不采用，不覆盖。

配置必须在开始时冻结并绑定新的 recording session；录制中改表单只作用于下一次。不能在收到一批数据时读取“网页当前标签”直接赋值，否则延迟上传会被错标。

若暂时不修改固件，可先在结束后选中准确 session 做人工标注，适用于先测试流程。完整自动流程宜由服务端保存当前待采任务，开始时由网关取得并锁定 task_id/session，后续批次都带该标识；等待标注确认或任务获取失败时必须在界面明确提示，不能默默套用上一任务。

SQLite 增加按 session 关联的样本标注表，不重复在每帧存姓名/词名。建议字段：sample_id、session、worker_id、label_id、label_text、v、active_hand、take_index、quality_status、notes、created_at。worker_id/label_id 使用稳定 ID；可改显示名但不改变历史动作的含义。完整句子样本另外保存 sentence_id 及词序列；如有连续词识别需求，还需逐词起止帧标注。

## 导出建议

保留原始归档导出，并新增明确命名的“分类数据集”导出，不替换现有导出按钮的数值语义。用户此前要求等全部标定完再决定最终原始寄存器数据集，因此此处先约定结构，不切换数值或单位。

兼容示例时保留前八列：

`worker,v,label,active_hand,sample_id,timestamp/ms,frame_id,hand_type`

其后按示例顺序放 10 路指部六轴及掌部字段。最终原始数据集应使用保存的寄存器整数，不从网页物理单位或校正显示反算。当前传感器量程配置、轴方向、左右手通道映射需要另存 manifest；列名相同并不代表新旧数据可以直接混合训练。

兼容模式建议 timestamp/ms 使用现有网关的对齐 timestamp_ms，两手同一配对共用；frame_id 使用 session 内 sequence，允许丢失后出现间断，不自动插值补齐。若要单独从片段起点重新编号，必须另留原 sequence 映射。

同一 sample_id、frame_id 下按 left、right 排行，缺手不能拿最近旧帧补齐。缺手、无效通道、无磁力计均为空，不填 0。用户此前要求移除磁力计显示；是否在最终兼容 CSV 保留其三列，需结合训练代码决定。若训练只用六轴，最终可采用明确版本的 74 列格式（8 元数据列＋66 六轴列）。不把 74 列冒充原示例的 77 列。

建议同时导出 manifest，包含 session、设备 ID、source_timestamp_ms 字段解释、量程、采样设置、通道有效率、配对缺失数、标定版本及采用的数值类型。严格兼容的 CSV 中不随意插入额外列，以免旧训练脚本按列位置读取出错。

分类下载可以提供：全部合并 CSV，按采集人/词元/速度筛选，或 ZIP 中按 `P001/词元ID/medium/样本ID.csv` 分文件。文件路径使用服务端生成的 ID，不直接拼接自由输入姓名或词语。

## P1–P13 候选采集词

下列是中文语义层面的采集清单，不是已确认的手语 gloss。相同动作只建一个类别，通过多次采集增加样本；如果同一中文词在不同语境使用不同手势，应分成不同手语词元。整句原文另外保留。

| 对话 | 候选词或固定表达 | 需确认处 |
|---|---|---|
| P1 | 你、好、很好、谢谢、早上 | “你好”是固定动作还是“你＋好”；“很好”是否为“很＋好”；“你好吗”的疑问如何表达 |
| P2 | 我、你、叫、什么、名字、很、高兴、认识、第一次、来、上海、是、志愿者、家、在、哪里、新疆、乌鲁木齐、几、岁、二十六、几口人、五、爸爸、妈妈、姐姐、哥哥、和 | “吗、啦”是否没有独立手势；26 和“五口”如何按数字/量词组合；“第一次、几口人、乌鲁木齐”是否拆分 |
| P3 | 欢迎、到、家、来、玩、请、坐、喝、茶 | 欢迎/请是否固定表达；喝茶是否一个词元 |
| P4 | 你们、房子、真、漂亮 | 你们是否“你＋复数”或一个整体；家与房子是否不同动作 |
| P5 | 祝、你、您、旅途、愉快、生日、快乐、新年、好、圣诞、身体、健康、工作、顺利、学习、进步 | 您与你是否同手势；新年好、生日快乐等是固定表达还是可组合词元 |
| P6 | 我、想、请、你、吃饭、谢谢、很、愿意、参加、我们、聚会、抱歉、有、事、来、看看、新居、好 | 我们/你们复数表达；看看是否看＋重复；新居是否新＋房子；愿意是否与想区分 |
| P7 | 十分、感谢、你、对、我、帮助、别客气 | 十分/很是否同类；感谢/谢谢是否同动作；“对、的”是否省略；别客气是否固定表达 |
| P8 | 很、抱歉、我、迟到、没关系 | “了”是否省略；没关系是否固定表达；很抱歉是否很＋抱歉 |
| P9 | 再见、一会儿、见、明天、晚安 | 一会见/明天见如何组合；晚安是否固定表达 |
| P10 | 先生、附近、有、银行、对不起、我、不知道 | 对不起/抱歉是否同动作；不知道是否不＋知道；疑问由手势还是非手部信息表达 |
| P11 | 你、想、买、什么、我、看看、那、件、衣服、请问、多少、钱、八十、元 | “件、元”是否独立词元；八十/多少钱如何切分；看看与看是否同类 |
| P12 | 你、哪里、不舒服、我、发烧、咳嗽、要、经常、锻炼、身体、不要、太、劳累 | “那儿不舒服”按语义应核对是否“哪儿”；不舒服/不要的拆分；经常是否独立表达 |
| P13 | 你、帮、我、买、票、能、打电话、好、有、什么、事、感冒、医生、叫、休息、两天、请假 | “那你帮我买票吗”是否“能帮我买票吗”；买票、打电话、两天、请假是否固定手语词；“了、吗”是否省略 |

## 先采哪些

第一轮先沿用示例已有的 10 类：我、你、好、早上、很、认识、谢谢、高兴、在、家。示例只能提供标签参考，实际动作必须统一。

第二轮建议加入高复用项：什么、名字、叫、哪里、有、来、请、想、愿意、帮、买、吃饭、身体、工作、学习、明天、见、抱歉、没关系、再见。若示范者确认某项是复合动作，按确认后的切分替换该项。

第三轮扩展 P1–P13 全部场景，包括地点、称谓、节日、医疗、数字等；依照同一 gloss 规范去重后再给出最终总类别数。不要先按中文字符数量决定模型类别。

同时采“静止/无目标动作”和日常非目标动作作为背景样本；从静止到词语动作再回静止，词起止可复核。手部 IMU不能直接记录表情、口型、视线，涉及疑问或强度的表达不一定能仅靠双手 IMU 区分，应在任务定义中明确。

先对少量词、每人每词 5–10 次自然速度做试采，检查动作时长、配对缺失和通道质量。流程稳定后，每人每词每速度 20–30 次可作为起步计划，不作为准确率保证。按人均衡、分多轮采，避免某个词只由某个人或某一种速度提供。慢/中/快三档沿用示例 slow/medium/high 命名，待用户确认。

训练/验证/测试按整次样本分组；同一样本的相邻帧、滑窗和左右手不能拆到不同集合。需要验证换人效果时，再以整个人作为留出对象。连续句子验证应另外采集，不用把独立词 IMU 简单拼接后当作真实连续手语数据。
